🏗️ Arquitectura del Sistema

La aplicación sigue el patrón de Clean Architecture con separación estricta en 3 capas independientes, garantizando mantenibilidad, testabilidad y escalabilidad.

🖥️ Presentation

Pages, Components, Pipes. Interacción con el usuario mediante Angular Signals.

⚙️ Domain / Core

Use Cases, Models, Interfaces. Lógica de negocio pura sin dependencias externas.

💾 Data

Repositories, Services. Implementación concreta de interfaces, acceso a datos.

Principios SOLID Aplicados

  • SRP — Cada clase tiene una única responsabilidad (use cases separados por operación)
  • DIP — Repositorios definidos como interfaces, implementados en la capa Data con tokens de inyección
  • OCP — Nuevas funcionalidades se agregan sin modificar código existente

🔥 Firebase y Remote Config

La integración con Firebase Remote Config permite controlar funcionalidades en tiempo real sin necesidad de redesplegar la aplicación.

🚩 Feature Flag: show_categories

✅ show_categories = true

  • Filtros de categorías visibles
  • Chips de colores en tareas
  • Barra de color lateral activa
  • Botón "Categories" visible
  • Módulo completo accesible

❌ show_categories = false

  • Filtros de categorías ocultos
  • Chips de colores ocultos
  • Barra lateral oculta
  • Botón "Categories" oculto
  • Módulo completamente inaccesible

Flujo de implementación

Firebase Remote Config
        ↓
RemoteConfigService.initialize()   ← Al arrancar la app
        ↓
RemoteConfigService.getShowCategories()  ← Retorna true/false
        ↓
TasksPage.showCategories (signal)  ← Actualiza estado reactivo
        ↓
tasks.page.html → @if(showCategories()) muestra/oculta UI

Configuración Anti-caché (desarrollo)

await remoteConfig.setConfigSettings({
  minimumFetchIntervalMillis: 0  // Sin caché en desarrollo
});

🌓 Dark / Light Mode

Sistema completo de temas con persistencia de preferencia del usuario mediante localStorage.

☀️ Light Mode

Fondos blancos, texto oscuro, sombras suaves.

🌙 Dark Mode

Fondos #0f0f1a, texto #f0f0ff, colores vibrantes.

ThemeService

@Injectable({ providedIn: 'root' })
export class ThemeService {
  isDarkMode = signal<boolean>(false);

  toggleTheme() {
    this.setDarkMode(!this.isDarkMode());
  }

  setDarkMode(isDark: boolean) {
    this.isDarkMode.set(isDark);
    isDark
      ? document.body.classList.add('dark')
      : document.body.classList.remove('dark');
    localStorage.setItem('darkMode', String(isDark));
  }
}

Computed Signals — Filtrado Reactivo

filteredTasks = computed(() => {
  let result = this.tasks();
  if (this.selectedCategoryFilter()) {
    result = result.filter(t => t.categoryId === this.selectedCategoryFilter());
  }
  if (this.searchQuery()) {
    result = result.filter(t =>
      t.title.toLowerCase().includes(this.searchQuery())
    );
  }
  return result;
});

Map O(1) — Búsqueda de Categorías

private categoryMap = computed(() => {
  const map = new Map<string, Category>();
  this.categories().forEach(c => map.set(c.id, c));
  return map;
});

getCategoryById(id: string | null): Category | undefined {
  return id ? this.categoryMap().get(id) : undefined;
}

❓ Preguntas de la Prueba Técnica

¿Cuáles fueron los principales desafíos?

1. Compatibilidad Cordova con Angular Standalone — Se resolvió configurando manualmente los builders ionic-cordova-build e ionic-cordova-serve en angular.json.

2. Incompatibilidad de Gradle con Cordova — Cordova no es compatible con Gradle 9.x. Se resolvió usando el wrapper interno de Gradle 8.13 generado por Cordova.

3. Caché de Remote Config — Firebase cachea valores por 1 hora. Se resolvió configurando minimumFetchIntervalMillis = 0 en desarrollo.

4. Dark Mode en componentes Ionic — Componentes como ion-select y ion-alert se renderizan fuera del shadow DOM, requiriendo estilos globales específicos.

¿Qué técnicas de optimización aplicaste y por qué?

Angular Signals con computed() para reactividad granular sin recálculos innecesarios. Lazy Loading para reducir el bundle inicial. Promise.all para carga paralela de datos. Map para búsqueda O(1) de categorías independiente del tamaño de la lista. TrackBy para evitar re-renders de items sin cambios. ngOnDestroy para liberar memoria al destruir componentes.

¿Cómo aseguraste la calidad y mantenibilidad?

Clean Architecture con separación estricta en 3 capas. Principios SOLID especialmente DIP mediante tokens de inyección. Tipado estricto con TypeScript. Commits descriptivos con convención feat:, fix:, perf:, chore: para trazabilidad completa.
